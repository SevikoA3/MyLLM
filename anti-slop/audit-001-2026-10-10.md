# MyLLM code and UI consistency audit

Date: 10 October 2026. Mode: antislop during, selected by the owner.

The scope is every existing route, its controls, and the shared loading, selection, error, persistence, and modal flows. This is maintenance of the implemented Phase 17 product. Background generation and command execution remain outside scope. No dependencies were added.

The owner initially authorized ADB inspection of Expo Go, then requested source-only auditing. Phone interaction stopped at that point. The observations below rely on source review and production component, hook, domain, and contract tests unless explicitly stated otherwise. They are not a complete native click-through or Android build certification.

## Reference patterns and design decisions

The official references establish interaction patterns, not an independent accessibility or design standard:

- [ChatGPT Android history](https://help.openai.com/en/articles/8167621-how-can-i-access-my-chat-history-in-the-chatgpt-android-app): history and starting a new conversation are explicit actions. MyLLM retains its existing tabs and uses plain History and New chat labels.
- [Claude model, effort, and thinking settings](https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings): model and reasoning controls are visible, named choices. MyLLM retains provider effort order and adds search to its existing model chooser.
- [DeepSeek App](https://api-docs.deepseek.com/news/news250115/) and [DeepSeek-V3.1](https://api-docs.deepseek.com/news/news250821/): thinking and search have distinct controls. MyLLM keeps thinking selection separate from tool approval and Web Tools configuration; it does not claim that the approval toggle enables search.

`DESIGN.md` remains authoritative: ENERGY 1, RHYTHM 1, MOTION 1. Existing Inter structure, JetBrains Mono data, dark surfaces, emerald primary actions, and restrained sheet motion remain. No brand assets, new destinations, or provider-specific behavior were invented.

| Decision | Purpose |
| --- | --- |
| Plain titles and shorter copy | Make the user's task recognizable without reading implementation terminology. |
| Remove fake startup progress and terminal dots | Show only measured or real state. |
| Scroll the Catalog header with records | Keep forms and the list reachable when content or font scale grows. |
| Wrap chat option controls | Keep tool approval discoverable instead of hiding it beyond horizontal scroll. |
| Search models by name and ID | Let users find both their custom labels and exact provider identifiers. |
| Neutral metadata badges and markdown emphasis | Reserve emerald for actions and meaningful activity. |
| Collapse reasoning initially | Keep the answer prominent while retaining access to reasoning summaries. |
| Review JSON before applying | Show changes across every endpoint before replacing the shared file. |
| Scroll selector and reset sheet contents | Keep longer menus reachable within the bounded modal. |
| Horizontal scrolling inside markdown tables | Preserve readable columns without making the whole transcript overflow. |

## Findings fixed

Priority reflects user impact. Rule references explain the UI issue; domain/security findings also follow `AGENTS.md` and `PLAN.md`.

1. **High, R-17/R-27/R-31:** startup displayed a hardcoded 62% progress bar and decorative diagnostic labels. Replaced with an indeterminate loader and an accurate resource label in `app/index.tsx`.
2. **High, R-26/R-27:** Setup replaced an unchanged custom endpoint name with a suggested hostname. It also allowed invalid model routes and could remain busy after an unexpected storage rejection. Effective form values are preserved; invalid paths block Connect; safe failures clear the key draft and release controls.
3. **Medium, R-05/R-15/R-31:** Setup repeated implementation labels and diagnostics before the user could connect. The main form now contains name, URL, key, and Connect. Existing auth/protocol/path options live in Advanced.
4. **High, R-27:** account usage and endpoint lists could spin forever after credential or storage reads rejected. Both now show recovery, retain navigation, and expose loading/disabled accessibility state. Usage discards obsolete completions after endpoint changes.
5. **Medium, R-03/R-26:** endpoint deletion actions had unconditional vertical flex, and imported endpoints lacked a direct edit action. Delete actions have normal targets; Edit selects the intended profile before opening Setup.
6. **High, R-27:** a rejected conversation load could look like a new empty chat and permit a send into a different conversation. Failed or missing requested histories now become read-only with a safe error, loading retry, and an explicit new-chat route.
7. **High, R-27:** the composer cleared its draft before preflight and persistence accepted the turn. It now clears after successful turn persistence; rejected preflight and local writes preserve the draft. Credential-read failure also releases the pending guard.
8. **Medium, R-27/R-31:** failed and cancelled responses displayed DONE; inherited Auto effort had no selected radio mark; reasoning opened by default. Status now reflects the actual turn, Auto is selected correctly, and reasoning is collapsed.
9. **Medium, R-03/R-26:** chat option controls hid tool approval offscreen; attachment removal used a 20 dp visual control. Options wrap and removal has a separate compact target with pending/disabled state. Composer focus, cursor, and send state are explicit.
10. **Medium, R-03/R-05/R-26:** model search ignored custom names, header/forms could consume the list area, refresh used a 36 dp target, and visibility-write failures were unhandled. Name/ID search, a scrollable list header, a compact refresh target, and safe save feedback correct these issues.
11. **High, R-27:** catalog load and refresh failures could leave busy states stuck. Results from a previous endpoint could replace current models because a shared alive flag became true again. Loaders catch failures and update state only for their captured current repository.
12. **High, R-26/R-27:** model drafts crossed model/endpoint identities, Save and Reset could overlap, and validation used saved limits rather than proposed metadata. Draft state resets by identity, writes are serialized, and the candidate override is previewed through production request validation before save.
13. **Medium, R-26/R-27:** missing models had no recovery and Reset silently removed custom-only records while claiming Server Defaults. Recovery remains navigable; reset uses inherited-value copy, warns about custom model removal, and returns after removal.
14. **High, R-27:** JSON editing could load forever without an endpoint, keep another endpoint's draft, report stale validation, lose edits during Apply, and reject without recovery. The editor is scoped by endpoint identity, handles missing data, locks conflicting actions, preserves failed drafts, and shows safe errors.
15. **High, R-26/R-31:** JSON Apply replaced all endpoint overrides while preview compared only the active endpoint. Preview now includes additions, changes, and deletions across all endpoints, reads current persisted overrides, and requires review before application. Export explicitly shares saved overrides.
16. **High, repository security contract/R-36:** arbitrary override metadata could contain explicit credential fields, and validation messages could display recognizable secrets. Boundary validation rejects credential-shaped fields and recognizable secret formats recursively; feedback is redacted. Copy no longer claims that arbitrary metadata or URLs are guaranteed absent.
17. **High, R-27:** Web Tools provider reads raced, a failed settings write left a new token paired with old settings, and Delete All could overlap writes. Provider results are versioned, operations are serialized, credential changes roll back after settings failure, and typed secrets clear after each save attempt. Deletion confirmation blocks conflicting writes.
18. **Medium, R-27/R-31/R-36:** Web Tools draft values appeared saved; health success could describe old input and imply authentication passed. Draft changes are labeled, provider choices expose checked state, controls lock during health checks, and success explicitly describes only gateway health.
19. **High, R-27:** history list, rename, and delete failures were unhandled. Recovery preserves safe drafts and records; deletion disables repeat confirmation and dismissal while pending.
20. **Medium, R-26/R-27:** history search could miss conversations beyond the first loaded page. Active filters fetch the remaining pages and display searching/error state; unfiltered startup remains paginated.
21. **Medium, R-03/R-25/R-31:** excessive accent badges and green markdown emphasis weakened hierarchy; wide tables lacked a scroll region; sheets duplicated backdrop accessibility targets. Metadata uses neutral surfaces, prose emphasis stays text-colored, tables scroll locally, and one backdrop button remains. Tab spacing and labels use shared tokens and tabs hide while the keyboard is open.

## Verification

- TypeScript: `npm run typecheck`, passed.
- ESLint: direct `npx eslint .`, passed.
- Jest: full `npm run test:ci`, 49 suites and 384 tests passed after cleanup. The two removed tests exercised unused scaffolding rather than active application behavior. Regression tests exercise real components, hooks, and production logic with I/O mocked at boundaries. New bug tests were observed failing before fixes.
- Node: compiled production test entries with `node tools/build-tests.mjs`; all 85 contracts passed with `node --test --test-concurrency=1 --test-timeout=60000 test/contract/*.test.mjs`.
- Diff: `git diff --check`, passed.
- Contrast: token calculation against background, low, standard, high, and control surfaces. Text minimum 11.10:1; muted minimum 8.40:1; outline minimum 4.51:1; primary minimum 5.64:1; secondary minimum 5.90:1. Disabled-state opacity was not treated as active text. Error headings use the light error token on raised surfaces.

An initial sandbox contract run could not bind localhost. The unrestricted parallel run then exposed an existing port collision: onboarding and protocol both use port 4133, causing a server startup wait. The complete sequential rerun passed. Test harness ports were not rewritten as part of UI maintenance.

## Remaining review limits

Before publishing, the owner requested unused-file cleanup. Removed the unreferenced SpaceMono font, `src/ui/components.tsx`, its `theme.ts` wrapper, `src/app-info.ts`, and the two tests that only exercised those unused modules. Removed the unreferenced `readyState` and `usesStoredCredential` helpers. Import/reference searches and fresh automated checks confirmed that active screens do not depend on them.

- Full device click-through, TalkBack, hardware keyboard, image permission, native share sheets, system browser handoff, and final animation/keyboard geometry remain manual. No Android build or Expo upgrade was run.
- Some legacy spacing/type sizes and focus treatments remain local literals. No competing palette or typography map was added; a blanket formatting/token refactor was avoided.
- Filtering very large conversation collections reads remaining summary pages. This preserves correctness with existing APIs; database search would be a separate change if measured scale requires it.
- Credential detection rejects explicit secret fields and recognizable formats. It cannot reliably recognize an opaque credential placed under an innocuous metadata name.
- Source review is not a guarantee that every asynchronous operation across independent screens is globally serialized. This patch locks the confirmed conflicts in each owning flow.
